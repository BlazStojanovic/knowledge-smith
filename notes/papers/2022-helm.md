# Holistic Evaluation of Language Models (HELM)

## Citation

- URL: https://arxiv.org/abs/2211.09110
- Authors: Liang, Bommasani, Lee, Tsipras, Soylu, Yasunaga, Zhang, Narayanan, Wu, + ~30 authors (Stanford CRFM)
- Year / venue: 2022 / TMLR 2023
- **Raw**: [[raw/papers/pdf/2022-helm]]

## Core Claim

LM evaluation should be holistic: measuring 7 metric categories (accuracy, calibration, robustness, fairness, bias, toxicity, efficiency) across 16 core scenarios under standardized conditions. Prior models covered only 17.9% of core HELM scenarios on average; HELM achieves 96% coverage across 30 models.

## Key Paper Ideas

- **Taxonomy-then-select benchmark design**: start top-down with explicit scenario × metric design space, select subset, state what is covered and missing. Contrasts with bottom-up accumulation (SuperGLUE, BIG-Bench).
- **Score matrix, not score vector**: each model gets a matrix (scenarios × metrics), not a single number. Deliberately avoids single-number aggregation — different stakeholders should weight by their own values.
- **Scenario = (task, domain, language) triple**: task taxonomized from ACL tracks, domain decomposed into (genre, demographic, time).
- **Perturbation-based robustness/fairness**: applies semantics-preserving perturbations (NL-Augmenter) for robustness, demographic term substitution for counterfactual fairness. Scalable alternative to requiring pre-existing demographic metadata.
- **Core + targeted structure**: 16 core scenarios get all 7 metrics; 26 targeted scenarios probe specific capabilities/risks with appropriate metrics.
- **Standardized adaptation**: identical 5-shot prompting with same format across all 30 models.
- **Explicit "what is missing" section**: presented as a feature of holistic design.

## Methodology

**Evaluation framework**: 7 metric categories applied to 16 core scenarios. 98/112 possible (scenario × metric) cells measured (87.5%). 26 additional targeted scenarios for deep-dive on knowledge, reasoning, memorization, disinformation, bias, toxicity.

**Metrics**: accuracy (scenario-specific), calibration (ECE), robustness (perturbation invariance/equivariance), fairness (counterfactual, demographic parity), bias (representation, stereotyping), toxicity (PerspectiveAPI), efficiency (denoised and idealized runtime).

**Standardization**: all models evaluated under identical 5-shot conditions. Same prompt format. No model-specific prompt tuning.

## Key Results

| Finding | Value |
|---|---|
| Prior model coverage of HELM scenarios (avg) | 17.9% |
| Post-HELM coverage | 96.0% |
| Total evaluation runs | 4,939 |
| Total tokens processed | 12.2B |
| API cost (commercial models) | $38,001 |
| GPU hours (open models) | ~19,500 |

Substantive findings: instruction-tuning dominance (text-davinci-002 top across accuracy, robustness, fairness); access-accuracy gap (closed > open consistently); code models outperform on reasoning (code-davinci-002 52.1% GSM8K vs text-davinci-002 35.0%); prompt sensitivity universal (30-80% accuracy swing for same model+scenario).

The taxonomy-then-select design principle applies to extending Poolside's eval coverage. The perturbation-based robustness methodology could augment existing Poolside evals.

## Key Follow-Ups / Jumping-Off Points

- HELM's refusal to aggregate into a single score is principled but impractical for training decisions — is there a middle ground?
- The 5-shot standardization penalizes models optimized for other adaptation methods — how to fairly compare instruction-tuned vs base models?
- Can the perturbation-based robustness methodology be automated for new eval construction?

## Caveats

- English only despite covering some varieties (AAE, ICE)
- 5-shot prompting only — results may not generalize to fine-tuning or CoT
- Train-test contamination unknown for many commercial models
- Statistical significance concerns: only 3 random seeds, 1000 instances
- Snapshot in time (late 2022) — landscape changed rapidly
- Automated metrics have known limitations (PerspectiveAPI for toxicity, ROUGE for summarization)
