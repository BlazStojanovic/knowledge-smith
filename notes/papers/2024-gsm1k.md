# Careful Examination of Large Language Model Performance on Grade School Math

GSM1k: a parallel holdout benchmark for GSM8k that detects benchmark contamination by comparing model performance on the original public test set against a new set of 1205 human-written problems with matched difficulty distribution.

## Citation

- **Authors**: Hugh Zhang, Jeff Da, Dean Lee, Vaughn Robinson, Catherine Wu, Will Song, Tiffany Zhao, Pranav Raja, Charlotte Zhuang, Dylan Slack, Qin Lyu, Sean Hendryx, Russell Kaplan, Michele (Mike) Lunati, Summer Yue (Scale AI)
- **Venue**: NeurIPS 2024 Datasets and Benchmarks Track
- **arXiv**: [2405.00332](https://arxiv.org/abs/2405.00332)
- **Raw PDF**: [[raw/papers/pdf/2024-gsm1k.pdf]]

## Core Contribution

Introduces **GSM1k**, a 1205-problem holdout benchmark mirroring GSM8k in style, difficulty, and answer-magnitude distribution. By comparing model accuracy on GSM8k vs. GSM1k, the paper provides a controlled measurement of benchmark overfitting / contamination. Key finding: accuracy drops of up to 8% on the overfit models, but frontier models show minimal signs of overfitting.

## Method: Parallel Holdout Design

The core methodology is a **parallel holdout** approach (inspired by Recht et al. 2019 on ImageNet):

1. **Human-only construction**: 1205 grade-school math problems created by human annotators, no LLMs used. Annotators were prompted with 3 GSM8k examples of matching difficulty and asked to produce novel problems.
2. **Difficulty matching**: Problems requested to match the distribution of resolution steps in GSM8k. Number of steps estimated by counting "calculator" tags in GSM8k solutions.
3. **Answer-magnitude matching**: Final problem selection filters candidates to match the answer-magnitude distribution of GSM8k as closely as possible (from 2108 initial candidates, 1375 passed quality, 1205 selected after magnitude matching).
4. **Quality assurance**: Three review layers — (a) trusted annotator review for correctness and grade-school-level math, (b) independent second solve by different annotators (problems discarded if second answer disagreed), (c) general quality audit by Scale.

### Difficulty Validation

- **Human distinguishability**: Annotators shown 4 GSM8k + 1 GSM1k problem and asked to find the odd one out. Identification rate: 21.83% out of 1205 attempts (20% = chance). Practically indistinguishable.
- **Human solve rates**: Under 15-minute time pressure, annotators solved 4.07 +/- 0.93 GSM8k problems vs. 4.36 +/- 1.11 GSM1k problems. GSM1k is comparable or slightly easier.
- **Pre-benchmark model sanity check**: GPT-NeoX-20B and GPT-2 (trained before GSM8k release) show minimal difference between GSM8k and GSM1k accuracy.

### Evaluation Setup

- Fork of EleutherAI LM Evaluation Harness. 5-shot prompting with GSM8k train examples (standard). Temperature 0 for open-source models. Max generation tokens increased from 256 to 1000.
- Automatic evaluation: extract last numeric answer, compare to ground truth.

### Systematic Family Patterns

- **Phi family**: Consistent overfitting across Phi-1.5, Phi-2, Phi-3-mini, Phi-3-medium.
- **Mistral family** (small models): Consistent overfitting across Mistral-7B, Mixtral-8x7B, Mixtral-8x22B — but **Mistral Large shows no overfitting**, suggesting sufficiently strong models generalize even if training data included GSM8k.
- **Yi, Xwin, Gemma, CodeLlama**: Also show overfitting to lesser extent.
- **Frontier models** (GPT-4, Gemini, Claude, Mistral Large): Minimal to no signs of overfitting.

### Log-Likelihood Analysis

Positive relationship between per-character log-likelihood of generating GSM8k test set and the GSM8k-GSM1k performance gap:

- **Spearman's r^2 = 0.36** (p = 0.03)
- Pearson r^2 = 0.26
- Kendall's tau = 0.29

Suggests partial memorization of the test set contributes to overfitting, but does not fully explain it.

## Four Lessons (paper's interpretation)

1. **Some model families are systematically overfit** — Phi and Mistral families show consistent overfitting across nearly all model sizes and versions.
2. **Frontier models show no signs of overfitting** — Possibly because (a) they have strong enough reasoning to generalize even if they saw GSM8k, or (b) frontier builders are more careful about contamination.
3. **Overfit models still reason** — Even the most overfit models solve many GSM1k problems. Phi-2 drops 6pp but still solves >50% of GSM1k (comparable to Llama-2-70B, a model 25x larger).
4. **Data contamination is not the full explanation** — Outliers include Math-Shepherd-Mistral-7B-RL (high overfitting but low log-likelihood, suggesting reward model leakage) and Llemma (high log-likelihood but minimal overfitting, despite confirmed small GSM8k presence in training data).

## Parallel Holdout as a General Contamination Detection Pattern

The paper operationalises a reusable methodology:

1. Create a new test set matching the original's difficulty distribution (human-written, no LLMs).
2. Validate equivalence: human solve rates, human distinguishability, pre-benchmark model controls.
3. Compare model accuracy on old vs. new set; the gap estimates contamination-driven overfitting.
4. Correlate gap with log-likelihood of generating original benchmark for a memorisation signal.

This is the same pattern used by Recht et al. (2019) for ImageNet/CIFAR-10, now applied to LLM math benchmarks. The approach complements functional evaluations (Srivastava et al. 2024) which generate infinite variations but only within narrow templates.

## Limitations

- GSM1k is only "highly similar" to GSM8k, not identically distributed. Remaining distributional differences could explain some portion of observed gaps.
- Difficulty matching is approximate: based on counting calculator tags, which is a rough proxy for actual problem difficulty.
- The paper cannot determine whether contamination occurred during pretraining or post-training.
- Closed-source model evaluation required sending data via API; benchmark integrity depends on providers not training on API data.
- The log-likelihood analysis (Spearman's r^2 = 0.36) is relatively low, with notable outliers, suggesting overfitting has multiple causes beyond direct data contamination.
- Open-source model results used temperature 0 for reproducibility; API models used default settings. Evaluation prompt standardised but may not match each model's optimal setting, so absolute GSM8k numbers may differ from reported benchmarks.
